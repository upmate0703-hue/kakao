## v9.2.0 — 밤새 돌리면 몇 번째부터 안 보내지던 문제 · 달력 오류

### 1. 밤새 돌리면 몇 번째 회차부터 안 보내집니다

30분 간격으로 걸어 두고 갔는데 세 번째쯤부터 아무것도 보내지 않았습니다.

**까닭**

발송이 끝나면 결과창이 뜹니다. 이 창은 예약 시계 안에서 뜹니다.
그런데 창을 **붙잡는 방식**으로 띄우고 있었습니다. 붙잡으면 예약 시계가 그 자리에서 멈춰 섭니다.

멈추면 두 가지가 한꺼번에 어긋납니다.

- 결과창의 "40초 뒤 저절로 닫힙니다" 시계도 같이 멈춥니다. 그래서 창이 저절로 닫히지 않습니다.
- 예약 시계도 멈춥니다. 그래서 다음 회차가 오지 않습니다.

즉, 실패가 하나라도 생겨 결과창이 뜬 회차부터 프로그램 전체가 그 창 앞에서 서 버립니다.
아침에 와서 창을 닫아 주기 전까지 한 번도 보내지 않습니다.

**고친 내용**

결과창과 알림창을 붙잡지 않고 띄우도록 바꿨습니다. 창이 떠 있어도 예약 시계는 그대로 돕니다.

실제로 재어 봤습니다.

| | 1회차 | 2회차 | 3회차 |
|---|---|---|---|
| 고치기 전 | 발송 | 멈춤 (영영) | — |
| 고친 뒤 | 발송 | 발송 | 발송 |

**안전장치도 하나 더 넣었습니다**

앞으로 예상 못 한 알림창이 떠도 밤샘 발송이 멈추지 않도록 지킴이를 넣었습니다.
예약이 걸려 있는데 윈도우 알림창이 2분 넘게 그대로 서 있으면 스스로 닫고 로그에 적습니다.
사용자가 열어 둔 설정 창은 건드리지 않습니다.

### 2. 달력을 누르면 오류가 납니다

예약 시각이 이미 지난 날짜로 남아 있으면 `[달력에서 고르기]` 를 누르는 순간 오류창이 떴습니다.
밤새 돌려 두었다가 다음 날 열면 늘 그랬습니다.

달력은 오늘보다 이른 날을 받지 못합니다. 지난 날짜를 넣으니 그 자리에서 터진 것입니다.
이제 지난 시각이면 오늘 기준으로 당겨서 보여 줍니다.

### 3. 기능을 하나하나 눌러 봤습니다

사람이 눌러야만 도는 코드는 배포 전에 오류를 모르고 지나갑니다.
그래서 검사 도구가 화면마다 단추를 전부 찾아 눌러 보도록 만들었습니다.

```
LAYOUT_OK   겹치는 화면 요소 없음
BUTTONS_OK  방 179개 · 전체 선택 179개
CLICK_OK    단추 31개를 눌러 보았고 오류가 없습니다
DIALOG_OK   창 8개가 모두 오류 없이 열립니다
SELFTEST_OK
```

지우거나 되돌리는 단추, 그리고 실제로 카카오톡에 보내는 단추는 누르지 않습니다.

같은 부류의 오류가 다시 들어오지 못하도록 검사도 넣었습니다.
결과창·알림창이 다시 '붙잡는 방식' 으로 바뀌면 자체 점검에서 바로 걸립니다.

## v9.1.1 — [전체 선택] 을 누르면 멈추던 문제

### 무엇이 잘못됐나

```
이 개체에서 'Key' 속성을 찾을 수 없습니다.
```

지난 판에서 여러 카카오톡을 지원하려고 방 항목에 `Key`(카카오톡 번호 + 방 이름) 칸을 넣었습니다.
그런데 **방 항목을 만드는 곳이 세 군데인데 한 군데에만 넣었습니다.**

| 어디서 만드나 | Key 칸 |
|---|---|
| [열어 둔 채팅방 읽기] | 있음 |
| 프로그램을 켤 때 저장된 목록 불러오기 | **없음** |
| [직접 추가] · [전체 목록 읽기] | **없음** |

[전체 선택] 을 누르면 고른 방을 저장하면서 모든 항목의 `Key` 를 읽는데,
그 칸이 없는 항목에서 멈췄습니다.

### 어떻게 고쳤나

**방 항목을 만드는 자리를 하나로 모았습니다.**

```powershell
function New-RoomEntry([string]$Name, [string]$Type, [bool]$Checked,
                       [string]$Kind, [bool]$Verified, [int]$Instance, [string]$Key) {
    ...
    return [pscustomobject]@{
        Name = ...; Key = ...; Instance = ...
        Type = ...; Checked = ...; Kind = ...; Verified = ...
    }
}
```

이제 어디서 만들든 같은 칸이 들어갑니다. 한 군데서 빼먹을 수가 없습니다.

### 다시 안 생기게 막았습니다

**① 칸이 빠졌는지 검사합니다.**

방 항목에 `Name · Key · Instance · Type · Checked · Kind · Verified` 일곱 칸이
모두 있는지 확인합니다. 하나라도 없으면 자체 점검이 실패합니다.

**② 단추를 실제로 눌러 봅니다.**

화면 검사에서 채팅방 화면을 열고 단추를 진짜로 누릅니다.

```
전체 선택 → 오픈채팅만 → 일반채팅만 → 보기 필터 → 전체 해제 → 검색 지우기
```

`전체 선택` 이 저장된 방을 **전부** 고르는지 숫자로 확인합니다.
하나라도 빠지거나 멈추면 검사가 실패합니다.

```
BUTTONS_OK 방 178개 · 전체 선택 178개
```

100 · 125 · 150% 배율에서 모두 통과했습니다.

> 단추는 화면이 보일 때만 눌립니다. 그래서 검사에서도 채팅방 화면을 먼저 연 뒤 누릅니다.
> 이것을 몰라서 처음에는 `전체 선택 0개` 가 나왔고, 그 덕에 검사가 제대로 도는지도 함께 확인됐습니다.

## v9.1.0 — 발송 결과 창이 발송을 막지 않게

### 무엇이 문제였나

발송이 끝나면 결과 창이 언제나 떴습니다. 두 가지가 잘못돼 있었습니다.

**① 잘 끝났는데도 창이 떴습니다.**
실패가 하나도 없으면 굳이 알릴 것이 없습니다.

**② 그 창이 다음 발송을 막고 있었습니다.**

```
발송 끝
  → 결과 창 띄움 (누를 때까지 서 있음)
  → 그 동안 프로그램은 아직 '발송 중' 상태
  → 예약 시각이 와도 "이전 발송이 진행 중" 으로 보고 이번 회차를 건너뜀
```

자리를 비우신 사이에 이 창이 떠 있으면 **예약 회차가 계속 건너뛰어졌습니다.**
반복 예약을 거는 것도 창을 닫은 뒤로 밀렸습니다.

### 어떻게 고쳤나

**① 실패가 있을 때만 창을 띄웁니다.**

잘 끝나면 아무 창도 뜨지 않습니다. 상태줄과 실행 기록에 이미 다 있습니다.

```
완료 · 성공 16개                    ← 상태줄에만
완료 · 성공 14 · 실패 2             ← 실패가 있으면 빨갛게
```

**② 발송 잠금을 창보다 먼저 풉니다.**

순서를 이렇게 바꿨습니다.

```
발송 끝
  → 발송 중 상태를 먼저 풂
  → 반복 예약을 먼저 걸어 둠
  → 그 다음에 결과 창
```

이제 결과 창이 떠 있어도 다음 예약 회차가 정상으로 돕니다.

**③ 결과 창은 40초 뒤 저절로 닫힙니다.**

자리를 비우셔도 창이 계속 서 있지 않습니다.
읽는 중에 창을 한 번 누르시면 자동으로 닫히지 않습니다.

```
전체 대상: 16개
성공:      14개
실패:      2개

발송 사진: 42장   ·   파일 3개   ·   메시지 14건

[실패한 채팅방 2개]
· 토토  —  ATTACH_NOT_LANDED 미리보기는 닫혔지만 …
· 업체B  —  ROOM_NOT_FOUND 카카오톡 채팅 목록에서 …

[보내기] 화면의 [실패한 방만 다시 보내기] 로 이 방들만 다시 보낼 수 있습니다.

              37초 뒤 저절로 닫힙니다.        [닫기]
```

실패한 방마다 **까닭까지 함께** 보여 줍니다. 기록을 열어 보지 않으셔도 됩니다.

**④ 예약이 스스로 돌 때는 묻는 창을 띄우지 않습니다.**

첨부 파일에 문제가 있으면 예전에는 이렇게 물었습니다.

```
첨부 파일 1개에 문제가 있습니다.
photo03.jpg - 파일을 찾을 수 없습니다

[예] 문제 있는 파일만 빼고 보냅니다.   [아니오] 시작하지 않습니다.
```

사람이 없는데 이 창이 뜨면 **발송이 거기서 멈춥니다.**
이제 예약이 스스로 돌린 것이면 묻지 않고, 문제 있는 파일만 빼고 진행한 뒤 기록에 남깁니다.

```
예약 발송이라 묻지 않고 문제 있는 파일만 빼고 진행합니다.
문제 있는 첨부 1개를 빼고 2개만 보냅니다.
```

오류로 중단됐을 때 뜨던 창도 같습니다. 사람이 있을 때만 뜨고, 그것도 30초 뒤 닫힙니다.
예약 발송일 때는 기록에만 남깁니다.

## v9.0.0 — 이모지 이름 보존 · 여러 카카오톡 [BETA] · UI 정리

### 1. 이모지가 잘리던 문제 — 원인과 고침

`자유로운홍보방❤️` 이 `자유로운홍보방` 으로 저장되던 원인은 두 군데였습니다.

**① 이름을 다듬는 코드가 이모지를 일부러 지우고 있었습니다.**

```
# 예전 코드 (Remove-RoomNameNoise)
# 이모티콘이나 그림 문자는 이름에서 뺍니다. 목록이 읽기 어려워집니다.
$isEmoji = ($code -ge 0x1F000 -and $code -le 0x1FAFF) -or ($code -ge 0x2600 -and $code -le 0x27BF)
$isSurrogate = ($code -ge 0xD800 -and $code -le 0xDFFF)
$isMark = ($code -ge 0xFE00 -and $code -le 0xFE0F) -or $code -eq 0x20E3
if ($isEmoji -or $isSurrogate -or $isMark) { continue }   ← 여기서 지웠습니다
```

이 코드는 프로그램을 켤 때마다 **저장된 이름에도** 돌았습니다.
그래서 창 제목에서 제대로 읽어 온 이름도 다음에 켜면 깎여 있었습니다.

**지웠습니다.** 이제 한 글자도 임의로 빼지 않습니다.

**② 파워셸의 문자열 비교가 이모지 변형표시를 무시하고 있었습니다.**

```
'자유로운홍보방❤️'  -ceq  '자유로운홍보방❤'   →  True   ← 잘못
```

`-ceq` 는 대소문자만 가릴 뿐, 이모지 뒤에 붙는 변형표시(U+FE0F) 같은 것을 없는 셈 칩니다.
그래서 서로 다른 두 방이 같은 방으로 합쳐졌습니다.

**글자 코드를 그대로 견주는 방식(Ordinal)으로 바꿨습니다.**

```powershell
function Test-NameEquals([string]$A, [string]$B) {
    return [string]::Equals($A, $B, [System.StringComparison]::Ordinal)
}
```

이름을 견주는 곳 15군데와, 이름을 열쇠로 쓰는 표 25군데를 모두 바꿨습니다.
파워셸이 기본으로 주는 표(`@{}`)도 느슨하게 견주기 때문에 `New-NameMap` 으로 바꿨습니다.

**③ 비슷한 이름을 합치던 것도 없앴습니다.**

프로그램을 켤 때 한 글자만 다른 이름을 같은 방으로 합치는 코드가 있었습니다.
`홍보방⭐` 과 `홍보방★` 이 합쳐질 수 있었습니다. 없앴습니다.

### 표시용 이름과 견주기용 값

- **표시·저장** — 카카오톡에 적힌 그대로입니다. 이모지도 특수문자도 그대로입니다
- **견주기** — 앞뒤 빈칸만 정리하고, 유니코드 표준 방식(NFC)으로 한 번 맞춥니다

같은 이모지를 컴퓨터마다 다르게 적어 두는 경우가 있어 NFC 로 맞춥니다.
**이모지를 지우고 견주는 방식은 쓰지 않습니다.**

### 시험한 이름

말씀하신 11가지를 그대로 검사에 넣었습니다.

```
자유로운홍보방 · 자유로운홍보방❤️ · 자유로운홍보방❤ · 자유로운홍보방🔥
🔥자유로운홍보방🔥 · 홍보방⭐ · 홍보방★ · 홍보방! · 홍보방:) · 투투 · 토토
```

각 이름에 대해 확인합니다.

1. 이름을 다듬어도 한 글자도 사라지지 않는가
2. 견주기 열쇠가 이름을 바꾸지 않는가
3. 제목 다듬기가 이름을 바꾸지 않는가
4. **11개 중 어느 둘도 같다고 하지 않는가** (55가지 짝을 모두 확인)
5. 저장했다 다시 읽어도 그대로인가
6. 이름으로 다시 찾을 수 있는가
7. 설정을 손질하는 과정에서 합쳐지지 않는가 (11개가 11개로 남는가)

실제 카카오톡에서도 열린 방 이름을 글자 코드까지 찍어 확인했습니다.

```
추억의 웹게임 하실분~  |  12글자  |  U+CD94 … U+007E   ← ~ 도 그대로
```

### 2. 여러 카카오톡 함께 쓰기  [BETA]

한 PC 에 카카오톡을 여러 개 켜 두고 쓰실 수 있습니다.

**가장 조심한 것은 이름이 같은 방입니다.**

```
카카오톡 1 의 '거래처'   ≠   카카오톡 2 의 '거래처'
```

이름만으로 가르면 한쪽에만 두 번 가거나 한쪽이 빠집니다.
그래서 방을 가릴 때 **카카오톡 번호 + 방 이름** 을 함께 봅니다.

```
카카오톡1|거래처
카카오톡2|거래처
```

카카오톡이 하나면 예전처럼 이름만 씁니다. **쓰시던 설정이 그대로 동작합니다.**

**[설정] → 여러 카카오톡 함께 쓰기 BETA**

```
사용 중인 카카오톡 수  [ 1 ] 개    [지금 확인]

카카오톡 1 · 정상 · 열어 둔 채팅방 4개
```

설정한 개수와 실제로 켜져 있는 개수가 다르면 이렇게 알려 드립니다.

```
설정 3개 / 지금 켜져 있는 것 2개 — 켜져 있는 것만 씁니다.
```

**없는 카카오톡 때문에 프로그램이 멈추지 않습니다.**

발송은 예전처럼 한 방씩 차례로 합니다. 카카오톡을 두 군데서 동시에 만지지 않습니다.
클립보드와 창 포커스가 엉키면 엉뚱한 곳에 붙기 때문입니다.

### 3. 발송 전 세부설정 창

`즉시발송` 이나 `예약 시작` 을 누르면 바로 나가지 않고 이 창이 먼저 뜹니다.

```
보낼 채팅방   16개
카카오톡      설정 1개 · 지금 켜짐 1개
메시지        안녕하세요. 오늘 안내드립니다.
첨부 파일     3개
사진 묶음     10장씩

### 16개에 3분이 걸리던 이유

### 채팅방 목록 읽기 — 놓치지 않게

스크롤이 너무 빨라 중간 방을 놓치는 문제를 고쳤습니다.

```
현재 화면 읽기
  → 보이는 줄 수보다 3줄 적게 내림 (앞뒤가 겹칩니다)
  → 화면이 실제로 움직인 것 확인
  → 움직임이 멈춘 것 확인
  → 다시 읽기
```

- **겹치게 내립니다.** 화면에 10줄이 보이면 7줄만 내려 3줄이 다시 보이게 합니다
- **움직인 것을 확인**한 뒤에 읽습니다. 흐르는 중에 읽으면 글자가 뭉갭니다
- 겹쳐서 같은 방이 여러 번 잡히면 **정확히 같은 이름일 때만** 하나로 칩니다.
  `투투` 와 `토토` 는 끝까지 다른 방입니다
- **끝났다고 보려면 두 가지가 모두 맞아야 합니다** — 더 내려가지 않고, 새 방도 안 나옵니다.
  맨 아래에 닿아도 바로 끝내지 않고 한 화면 더 읽습니다
- 다 읽으면 이렇게 알려 드립니다

```
총 87개 채팅방을 찾았습니다.

일반채팅 54개
오픈채팅 33개

### 즉시발송 · 예약 시작 · 예약 중지

상단이 이렇게 바뀝니다.

```
[내용 수정]  [즉시발송]  [예약 시작]  [?]
                          ↑ 예약이 켜지면 [예약 중지] 로 바뀝니다
              ↑ 보내는 중이면 [중지] 로 바뀝니다
```

그 옆에 상태가 한 줄로 나옵니다.

```
● 준비됨    예약 실행 중 · 10분 간격 · 다음 발송 09-02 19:20 · 실제 발송
● 준비됨    예약 중지 · 실제 발송
```

- **즉시발송** — 지금 한 번만 보냅니다. 예약과 아무 상관이 없습니다.
  예약이 생기거나 예약 시각이 바뀌지 않습니다
- **예약 시작** — 누르는 순간 지금 설정이 저장되고 예약이 켜집니다.
  따로 저장 단추를 찾을 필요가 없습니다
- **예약 중지** — 예약을 끕니다

상단의 [예약 시작] 과 [보내기] 화면의 [예약 시작] 은 **같은 함수**를 씁니다.
어디서 눌러도 같은 일이 일어나고, 타이머가 여러 개 생기는 일은 없습니다.

### 예약 시작해도 무조건 보내지는 않습니다

방금 즉시발송으로 보냈는데 예약을 켰다고 또 보내면 받는 분이 두 번 받습니다.

```
18:00  즉시발송 성공
18:01  예약 시작 (10분 간격)
       → 최근 발송이 확인되어 지금은 보내지 않습니다
       → 다음 발송 18:10
```

판단 기준은 **실제로 발송에 성공한 시각**입니다.
즉시발송을 눌렀지만 실패했다면 성공으로 치지 않습니다.

`다음 발송 = 마지막 성공 시각 + 예약 간격` 으로 잡습니다.
그래서 같은 방에 예약 간격보다 짧은 사이에 두 번 가지 않습니다.

예약을 켤 때 이렇게 알려 드립니다.

```
예약을 켭니다.

· 보낼 방: 16개
· 다음 발송: 2026-09-02 18:10:00
· 반복: 10분마다

· 최근 발송 18:00 · 중복을 막으려고 지금은 보내지 않습니다

계속할까요?
```

발송 중에 예약 시각이 오면 시작하지 않고 기록에 `OVERLAP_SKIP` 을 남긴 뒤,
끝나면 다음 시각으로 옮깁니다. 카카오톡을 만지는 일꾼은 언제나 하나입니다.

### 정확도는 그대로입니다

속도를 위해 없앤 확인은 **하나도 없습니다.** 없앤 것은 중복과 낭비뿐입니다.

| 확인 | 그대로인가 |
|---|---|
| 창 제목이 정확히 같을 때만 보냄 (`투투 ≠ 토토`) | 그대로 |
| 미리보기가 닫힌 뒤 대화창에 올라온 것까지 확인 | 그대로 |
| 입력칸이 비워진 것 + 대화창 변화 둘 다 확인 | 그대로 |
| 클립보드에 넣은 파일 되읽어 확인 | 그대로 |
| 첨부 파일 미리 검사 + 붙이기 직전 재검사 | 그대로 |
| 고른 방 = 성공 + 실패 (누락 0) | 그대로 |
| 사진 묶음 발송 (30장 / 10장씩 = 미리보기 3번) | 그대로 |
| 이미 보낸 사진은 다시 안 보냄 | 그대로 |
| 중간에 꺼져도 이어서 발송 | 그대로 |

바뀐 것은 **얼마나 오래 기다릴지** 하나뿐입니다.

4. 더 빠르게 하고 싶으시면 발송 속도를 **초고속** 으로

기록에 단계별 숫자가 남으니 어디가 느린지 바로 아실 수 있습니다.

## v7.1.0 — 속도 최적화 (안정성은 그대로)

### 무엇이 느렸나 — 재 보고 찾았습니다

`Start-Sleep` 을 눈으로 훑는 대신, 카카오톡 없이 도는 측정 장치를 만들어 실제로 쟀습니다.

| 조각 | 1회 비용 | 100방 환산 |
|---|---|---|
| 창 목록 훑기 (`Get-OpenChatRooms`) | 14~25ms | **1.6~2.5초** |
| 창 그림 뜨기 (`PrintWindow`) | 18.5ms | — |
| 대화창 모습 확인 | 18~19ms | — |
| 기록 한 줄 | 1.13ms | 1.1초 |

그리고 **확인 주기가 200~220밀리초로 못 박혀** 있었습니다.
카카오톡이 10밀리초 만에 준비돼도 200밀리초를 더 기다렸습니다.

### 무엇을 고쳤나

#### ① 확인 주기를 PC 속도에 맞춰 스스로 정하게

확인 한 번이 실제로 몇 밀리초 걸리는지 최근 20번을 기억해 두고, 그 2.5배를 주기로 씁니다.

```
빠른 PC : 확인이 10ms  →  25ms 마다 확인  →  준비되자마자 다음 단계
느린 PC : 확인이 90ms  →  225ms 마다 확인 →  CPU 를 덜 씁니다
```

실제로 잰 값입니다.

| 속도 설정 | 빠른 PC | 느린 PC |
|---|---|---|
| **자동** (기본값) | **20ms** | **225ms** |
| 빠르게 | 25ms | 25ms |
| 기본 | 60ms | 60ms |
| 안정적 | 200ms | 200ms |

**확인하는 횟수는 하나도 줄이지 않았습니다.** 기다리는 시간만 줄였습니다.

#### ② 창 목록을 방마다 다시 훑지 않게

`Find-OpenChatWindow` 가 방마다 카카오톡 창 50여 개를 전부 다시 훑고 있었습니다.

한 회차 동안만 기억해 두고 씁니다. **그래도 안전합니다** — 기억한 창을 그냥 쓰지 않고,
쓰기 직전에 ⑴ 그 창이 아직 살아 있는지 ⑵ 제목이 정확히 같은지 다시 봅니다.
둘 중 하나라도 어긋나면 기억을 버리고 다시 훑습니다.
회차가 바뀔 때마다도 비웁니다. 그 사이 사용자가 창을 열거나 닫았을 수 있으니까요.

실제 카카오톡에서 잰 값입니다.

```
매번 다시 훑기   14.2ms  →  기억해 두고 쓰기   1.2ms   (12배)
이름으로 창 찾기 16.8ms  →                     0.6ms   (28배)
```

#### ③ 기록을 모아서 쓰기

한 줄마다 파일을 열고 쓰고 닫고, 화면까지 다시 그렸습니다.
방 하나에 열 줄이면 100개 방에서 파일을 천 번 여닫습니다.

이제 모아 두었다가 **0.7초마다, 또는 40줄이 모이면** 한 번에 씁니다.
발송이 끝나거나 창을 닫을 때 남은 것을 반드시 씁니다. **기록은 한 줄도 빠지지 않습니다.**
화면에는 최근 1200줄만 두고 넘치면 800줄로 줄입니다. 파일에는 전부 남습니다.

```
1000줄(100방 × 10줄) 쓰기: 0.67초   (1줄 0.67ms)
화면 줄 수: 계속 쌓이지 않고 일정하게 유지
```

#### ④ 화면 다시 그리기를 0.2초에 한 번으로

방마다 상태가 바뀔 때마다 표 전체를 다시 그리고 `DoEvents` 를 불렀습니다.
이제 0.2초에 한 번만 손봅니다. 발송 중에도 화면이 멈추지 않고, 그리느라 느려지지도 않습니다.

### 얼마나 빨라졌나 — 실제로 잰 숫자

**진짜 창을 띄워 놓고** 실제 대기와 화면 캡처 비용을 그대로 재었습니다.
`Wait-ChatWindowReady`, `Wait-ChatContentSettled`, `Get-ChatTailSignature` 는 전부 진짜를 썼습니다.

### 10분 예약과 겹칠 때

`10분마다` 로 두었는데 한 번 도는 데 15분이 걸리면 이렇게 합니다.

### 안정성은 하나도 빼지 않았습니다

속도를 위해 없앤 확인은 **하나도 없습니다.**

- 창 제목이 정확히 같을 때만 보냅니다 (`투투 ≠ 토토`)
- 미리보기가 닫힌 것만으로 완료하지 않고, 대화창에 올라온 것까지 확인합니다
- 클립보드에 넣은 파일이 그대로 있는지 되읽어 확인합니다
- 첨부 파일을 미리 검사하고, 붙이기 직전에 한 번 더 봅니다
- 고른 방은 반드시 성공 아니면 실패로 끝납니다 (`성공 + 실패 = 전체`)
- 사진 묶음 발송은 그대로입니다 (30장 / 10장씩 = 미리보기 3번)
- 첨부가 없으면 첨부 관련 단계를 아예 지나갑니다. 문구가 없으면 문구 단계를 지나갑니다

바뀐 것은 **기다리는 방식** 하나뿐입니다.

## v7.0.0 — 운영용 안정화 · 새 아이콘

### 무엇이 문제였고 무엇을 바꿨나

#### 1. "보냈다"의 기준을 올렸습니다

예전에는 미리보기 창이 닫히면 보냈다고 봤습니다.
그런데 **취소를 눌러도 창은 닫힙니다.** 그러면 안 보냈는데 완료가 됩니다.

이제는 이렇게 합니다.

```
보내기 전 대화창 모습을 적어 둔다
  → 붙인다 → 미리보기 뜬 것 확인 → 전송 누른다
  → 미리보기가 닫힌 것 확인
  → 대화창 모습이 바뀐 것 확인   ← 여기가 새로 생겼습니다
  → 그때서야 성공
```

바뀐 것을 확인하지 못하면 `ATTACH_NOT_LANDED` 로 실패 처리하고 다시 시도합니다.

#### 2. 시간이 아니라 상태를 봅니다

`몇 초 기다림 → 다음 단계` 로 넘어가는 곳을 없앴습니다.
지금은 모두 이런 모양입니다.

```
조건이 만족될 때까지 짧게 반복해서 확인한다 (0.12초 간격)
  → 만족되면 즉시 다음 단계
  → 정해 둔 시간까지 만족 안 되면 그때 실패
```

설정의 대기 시간은 **최대 몇 초까지 기다릴지** 를 뜻합니다.
느린 PC 에서는 그만큼 더 기다리고, 빠른 PC 에서는 확인되는 즉시 넘어갑니다.

#### 3. 화면 배율에 따라 좌표가 어긋나던 곳

미리보기 창의 [전송] 자리를 **창 아래에서 24픽셀** 로 잡고 있었습니다.
150% 화면에서는 그 자리가 36픽셀이라 엉뚱한 데를 눌렀습니다.

이제 **그 창이 놓인 모니터의 배율을 물어**(`GetDpiForWindow`) 그만큼 늘려 잡습니다.
모니터마다 배율이 다른 듀얼 모니터에서도 각 창 기준으로 계산합니다.
그리고 한 자리만 노리지 않고 아래에서 24 · 34 · 18 · 46픽셀, 오른쪽 아래까지
차례로 눌러 보고, 그래도 안 되면 Enter 를 씁니다.

채팅창 아래 아이콘 줄은 원래부터 좌표가 아니라 **입력칸 위치를 기준으로** 찾고 있어
배율과 해상도에 영향을 받지 않습니다.

#### 4. 카카오톡이 잠깐 먹통일 때

`IsHungAppWindow` 로 응답 없음 상태를 알아냅니다.
먹통이면 바로 실패로 몰지 않고 **최대 20초까지 돌아오기를 기다렸다가** 이어서 합니다.
계속 응답하지 않으면 `KAKAO_NOT_RESPONDING` 으로 그 방만 실패 처리합니다.

#### 5. 클립보드

넣은 뒤 **되읽어 확인합니다.** 우리가 넣은 그 파일이 아니면 최대 5번까지 다시 넣습니다.
이 확인이 앞 채팅방에 쓰던 사진이 다음 방에 붙는 일도 막습니다.

끝나면 원래 클립보드를 돌려놓습니다. 글이든 파일 목록이든 그대로 복원하고,
원래 비어 있었다면 우리가 넣은 것을 지웁니다. 오류로 중단돼도 `finally` 에서 복원합니다.

#### 6. 오류 뒤 화면 되돌리기

한 단계라도 잘못되면 다음 방으로 넘어가기 전에 이 순서로 되돌립니다.

```
① 남아 있는 미리보기 창 닫기
② 남아 있는 파일 선택창 닫기
③ 채팅창 팝업 걷어내기
④ 입력칸에 남은 첨부 초안 치우기
```

되돌리지 못하면 그 방을 실패로 두고 다음 방으로 갑니다.
팝업이 뜬 채로 다음 일을 시작해서 엉뚱한 곳에 입력되는 일이 없습니다.

#### 7. 첨부 파일 미리 검사

시작 전에 파일을 한 번 훑습니다.

- 파일이 있는지
- 0바이트가 아닌지
- 300MB 를 넘지 않는지
- **실제로 열리는지** (다른 프로그램이 붙잡고 있으면 여기서 걸립니다)

문제가 있으면 프로그램이 멈추지 않고 파일마다 까닭을 보여 줍니다.

```
photo03.jpg - 파일을 찾을 수 없습니다
빈파일.jpg - 파일이 비어 있습니다 (0 바이트)
보고서.pdf - 다른 프로그램이 쓰고 있어 열 수 없습니다
```

그 자리에서 [문제 있는 파일만 빼고 보내기] / [시작하지 않기] 를 고르실 수 있습니다.
붙이기 직전에도 한 번 더 봅니다. 목록에 넣은 뒤 지워졌을 수 있기 때문입니다.

#### 8. 중간에 꺼져도 이어서 보냅니다

`progress.json` 에 진행 상태를 실시간으로 적습니다.
**한 방이 끝날 때마다, 그리고 사진 묶음 하나가 나갈 때마다** 적습니다.

```json
{ "Name": "다방", "Status": "실패",
  "MessageSent": true,
  "SentFiles": ["p1.jpg", "p2.jpg"] }
```

프로그램이 강제 종료되거나 PC 가 재부팅돼도, 다시 켜면 [보내기] 화면의
**[이어서 발송 (N개 남음)]** 이 켜집니다. 이미 보낸 방과 **이미 나간 사진 묶음은
다시 보내지 않습니다.**

문구가 바뀌었으면 이어서 보내기 전에 알려 드립니다. 앞뒤가 다른 글이 나가면 안 되기 때문입니다.

#### 9. 실패한 방만 다시 보내기

발송이 끝나면 **[실패한 N개 다시 보내기]** 가 켜집니다.
성공한 방은 건드리지 않고, 실패한 방의 이미 나간 사진도 다시 보내지 않습니다.

#### 10. 결과 화면

끝나면 이렇게 보여 드립니다.

```
전체 대상: 125개
성공:      123개
실패:      2개
누락:      0개

발송 사진: 1,230장
발송 파일: 52개
메시지:    123건

[실패한 채팅방 2개]
토토
업체B
```

**누락이 0이 아니면 제목이 [발송 완료 — 확인 필요] 로 바뀝니다.**

#### 11. 상세 기록

방 이름을 앞에 붙여 단계마다 남깁니다.

```
16:20:01  [뽀식] 채팅방 확인 시작
16:20:02  [뽀식] 채팅방 확인 성공
16:20:03  [뽀식] 첨부 묶음 1/2 붙여넣기 (10장 묶음)
16:20:06  [뽀식] 첨부 묶음 1/2 전송 성공 — a.jpg, b.jpg …  [붙여넣기 (미리보기 창 확인) / 미리보기 창의 전송 누름]
16:20:09  [뽀식] 첨부 묶음 2/2 전송 성공
16:20:10  [뽀식] 메시지 입력
16:20:11  [뽀식] 메시지 전송 성공
16:20:11  [뽀식] 발송 완료
16:21:11  [토토] 첨부 묶음 2/2 실패 — ATTACH_NOT_LANDED …
16:21:11  [토토] 일부 파일 전송 실패 — …
```

상태도 나눠 적습니다.

- `일부 파일 전송 실패` — 문구는 갔고 일부 사진만 못 갔습니다
- `파일 전송 실패 (문구는 보냄)` — 문구만 갔습니다
- `전송 실패` — 아무것도 못 갔습니다

#### 12. 새 아이콘

보내 주신 아이콘으로 바꿨습니다. **16 · 24 · 32 · 48 · 64 · 128 · 256** 일곱 크기를
한 파일에 담았습니다.

적용한 곳:

| 어디 | 어떻게 |
|---|---|
| EXE 파일 | 빌드할 때 app.ico 를 박습니다 |
| 창 왼쪽 위 · 작업 표시줄 · Alt+Tab | 프로그램 안에 담은 아이콘을 씁니다 |
| 대화상자 · 시작 화면 | 같은 아이콘 |
| 바탕화면 · 시작 메뉴 바로가기 | EXE 를 가리키므로 같은 아이콘 |
| 설치 프로그램 | `SetupIconFile` |
| 프로그램 제거 목록 | `UninstallDisplayIcon` |

작업 표시줄에서 예전 아이콘이 나오던 문제는 두 가지를 고쳐 잡았습니다.

1. 예전에는 EXE 에서 32x32 하나만 꺼내 썼습니다. 125·150% 화면에서는 그것을
   늘려 쓰느라 흐릿했습니다. 이제 크기별 아이콘을 프로그램 안에 담아 두고
   화면 배율에 맞는 것을 씁니다.
2. `SetCurrentProcessExplicitAppUserModelID` 를 넣었습니다.
   이것이 없으면 스크립트로 실행할 때 파워셸 아이콘으로 묶여 버립니다.

> 그래도 예전 아이콘이 남으면 윈도우가 캐시를 붙잡고 있는 것입니다.
> 작업 표시줄에서 고정을 풀었다가 다시 고정하시거나, 아래를 한 번 돌리고 로그아웃했다 들어오세요.
> `ie4uinit.exe -show`

### 누락을 막는 구조

고른 방은 반드시 **성공** 아니면 **실패** 로 끝납니다. 세 겹으로 막습니다.

```
① 열려 있는 창으로 보낸다                        (가장 빠르고 정확)
② 남은 방은 카카오톡 목록에서 이름으로 찾는다
③ 그래도 남으면 목록의 모든 줄을 하나씩 열어 확인한다
④ 끝까지 못 보낸 방은 ROOM_NOT_FOUND 로 실패 처리한다
```

④ 가 있어서 조용히 사라지는 방이 없습니다.
그리고 끝난 뒤 `성공 + 실패 ≠ 전체` 이면 프로그램이 스스로 `COUNT_MISMATCH` 를
기록에 남기고, 결과 화면 제목이 [확인 필요] 로 바뀝니다.

실패한 방은 회차마다 목록에 남겨 두고 다시 시도합니다 (기본 3회, 설정에서 0~5회).
회차가 끝나야 실패로 확정합니다.

### 무엇을 어떻게 시험했나

실제 메시지는 한 통도 보내지 않았습니다. 요청하신 대로입니다.

**카카오톡 없이 도는 시험** (`-SelfTest`) — 모두 통과

| 무엇을 | 어떻게 확인 |
|---|---|
| 누락 0 | 가짜 방 7개로 전체 흐름을 돌려 `7 = 완료 6 + 실패 1`, 상태표 7칸이 모두 완료/실패 |
| 비슷한 이름 | `투투 ≠ 토토`, `뽀식 ≠ 포식`, `우리반 공지방 ≠ 우리반 공지방 2기` |
| 엉뚱한 방 방지 | `우리반 공지방` 을 찾다 `우리반 공지방 2기` 가 열리면 안 보내고 닫는지 |
| 글자 잘못 읽어도 | 화면에 `포식` 으로 읽히는 `뽀식` 방을 끝내 찾아내는지 |
| 글자 못 읽어도 | 화면 글자가 아예 안 읽히는 방도 모든 줄을 열어 찾아내는지 |
| 열린 창 우선 | 목록을 아예 못 읽는 상황에서 열린 창 3개만으로 3개 다 보내는지 |
| 열린 창 안 닫기 | 사용자가 연 창을 닫으려 하면 시험이 실패하도록 |
| 창 가려내기 | 툴팁·알림·메인 창·미리보기·프로필 창 12가지를 걸러 내는지 |
| **이어서 발송** | **사진 4장을 2장씩 보내다 2번째 묶음 실패 → 파일에서 되살려 이어서 → p3·p4 만 나가고 p1·p2 는 다시 안 나감** |
| 묶는 규칙 | 사진만/사진+문서/묶기 끔/0장/999장 7가지, 순서 유지 |
| 첨부 검사 | 없는 파일·빈 파일·잠긴 파일·빈 경로를 걸러 내고 까닭에 파일 이름이 들어가는지 |
| 화면 배율 | 배율 값이 96~480 범위인지, 96/120/144 에서 누를 자리가 24/30/36 으로 늘어나는지 |
| 저장 메시지 | 저장·불러오기·덮어쓰기·삭제, 줄바꿈 유지 |
| 이모지 이름 | `나만의 대표님😘` 과 이어 붙인 이모지가 상하지 않는지 |

**화면 시험** (`-UiSmokeTest`) — 100 / 125 / 150% 배율에서 겹치는 곳 없음

**실제 카카오톡** — 아무것도 보내지 않고 확인한 것

- 열린 채팅방 창 읽기 — 카카오톡 프로세스의 창 50여 개(툴팁·타이머·IME·메인 창) 중
  **열려 있는 채팅방 1개만** 정확히 집어냅니다
- 목록 전체 읽기 — 110개 방을 20화면에 걸쳐 14초에 읽습니다
- 여러 파일 클립보드 — 사진 3장을 담았다 되읽어 3장 그대로, 원래 클립보드는 복원
- 이 컴퓨터의 화면 배율(96 = 100%)을 `GetDpiForWindow` 로 바르게 읽습니다
- 첫 실행 청소 — 빈 폴더에 남의 기록을 심어 두고 켜니 로그 0개, 설정 0개

### 직접 확인해 주셔야 하는 것

제가 메시지를 보낼 수 없어 아래는 확인하지 못했습니다.

- 실제 발송 (사진 1장 / 10장 / 30장 / 사진+PDF / 메시지만 / 첨부만)
- 오픈채팅방 발송
- Windows 10 · 다른 해상도 · 듀얼 모니터 · 125%·150% 실제 화면
- 발송 도중 프로그램을 강제 종료한 뒤 [이어서 발송]

**권해 드리는 순서**

1. 테스트 방 1개 · 사진 1장 · [설정] 화면의 [테스트 발송]
2. 테스트 방 1개 · 사진 10장 (묶음 동작 확인)
3. 테스트 방 2~3개 · 사진 + PDF (묶음이 나뉘는지, 순서가 지켜지는지)
4. 사진 10장을 보내는 도중 프로그램을 강제 종료 → 다시 켜서 [이어서 발송]
   → 같은 사진이 두 번 오지 않는지
5. 그다음에 실제 방으로

무엇이 막히든 [실행 기록] 화면과 `logs` 폴더의 그날 로그를 보시면
`[방이름] 어느 단계` 까지 나와 있어 어디서 멈췄는지 바로 아실 수 있습니다.

## v6.3.0 — 사진을 묶어서 한 번에 보냅니다

### 왜 묶는 편이 나은가

사진을 한 장씩 보내면 카카오톡이 이 일을 사진 수만큼 되풀이합니다.

```
붙이기 → 미리보기 창 뜸 → 전송 누름 → 창 닫힘 → 다음 사진 …
```

이 되풀이 중 어느 한 번이라도 미리보기 창이 늦게 뜨거나 늦게 닫히면 거기서 막혔습니다.
사진이 많을수록 막힐 자리가 늘어났습니다.

묶어 보내면 이렇게 한 번으로 끝납니다.

```
10장을 한꺼번에 붙이기 → 미리보기 창 한 번 뜸 → 전송 한 번 → 끝
```

### 어떻게 묶는가

[1. 보낼 내용] 화면의 첨부 칸 아래에 생겼습니다.

```
☑ 사진은 묶어서 한 번에 보내기    한 번에 [10] 장씩
```

- 기본값은 **켜짐 · 10장씩** 입니다. 1~30장까지 정하실 수 있습니다
- **문서와 그 밖의 파일은 하나씩 보냅니다.** 카카오톡이 그렇게만 받습니다
- **순서는 정하신 그대로 지킵니다.** 사진 사이에 문서가 끼어 있으면 그 앞뒤로 묶음이 나뉩니다.
  묶으려고 순서를 바꾸지 않습니다

예를 들어 이렇게 넣으셨다면

```
사진1.jpg  사진2.png  안내.pdf  사진3.jpg  사진4.jpg
```

이렇게 세 번에 나갑니다.

```
① 사진1 · 사진2  (묶음)
② 안내.pdf       (혼자)
③ 사진3 · 사진4  (묶음)
```

### 붙이는 방법

- **사진 묶음** — 파일 목록을 통째로 클립보드에 담아 Ctrl+V 로 붙입니다.
  안 되면 파일 선택창에 탐색기와 같은 방식으로 경로를 나열합니다.
  `"C:\사진\1.jpg" "C:\사진\2.jpg" "C:\사진\3.jpg"`
- **문서** — 파일 선택창을 먼저 씁니다. 안 되면 클립보드로 붙입니다.

장수가 많으면 미리보기가 뜨고 전송이 끝나기까지 더 걸립니다.
그만큼 기다리는 시간을 늘려 잡습니다. (장당 0.4초 더 기다리고, 보낼 때는 0.6초 더 기다립니다)

### 다시 할 때 같은 사진을 또 보내지 않습니다

묶음이 실패해서 다시 하더라도, 이미 나간 묶음의 사진은 빼고 남은 것만 다시 묶습니다.
방마다 어느 파일까지 나갔는지 따로 적어 두기 때문입니다.

한 묶음이라도 못 보내면 그 방은 **실패** 입니다. 못 보낸 것을 완료라고 하지 않습니다.

### 확인한 것

묶는 규칙은 카카오톡 없이도 시험할 수 있게 따로 떼어 두었습니다 (`Group-AttachmentBatches`).
자체 점검에 이런 경우를 넣었습니다.

| 넣은 것 | 설정 | 나와야 할 결과 |
|---|---|---|
| 사진 4장 | 묶기 끔 | 4묶음 (하나씩) |
| 사진 4장 | 10장씩 | 1묶음 |
| 사진 4장 | 2장씩 | 2묶음 |
| 사진2 · 문서 · 사진2 | 10장씩 | 3묶음 (문서는 혼자) |
| 빈 목록 | — | 0묶음 |
| 사진 4장 | 0장씩 | 4묶음 (1로 봄) |
| 사진 4장 | 999장씩 | 1묶음 (30으로 봄) |

모든 경우에 **순서가 그대로 남는지** 도 함께 확인합니다.

실제 클립보드에 사진 3장을 담았다가 되읽어 3장이 그대로 들어가는 것도 확인했습니다.

## v6.1.0 — 열어 둔 채팅방 창을 그대로 읽습니다

### 가장 정확한 방법을 기본으로 삼았습니다

사용자가 카카오톡에서 보낼 채팅방을 **창으로 열어 두면**, 그 창들을 그대로 읽습니다.

```
카카오톡에서 보낼 방을 두 번 눌러 창으로 연다
  → [열어 둔 채팅방 읽기]
  → 열려 있는 방이 그대로 목록에 들어오고 발송 대상으로 체크됨
  → 발송 시작
```

**창 제목이 곧 방 이름입니다.** 화면 글자를 읽지 않습니다.
그래서 `뽀식` 을 `포식` 으로 잘못 읽는 일이 **아예 일어날 수 없습니다.**
목록을 스크롤할 일도, 줄을 찾을 일도 없습니다.

읽어 온 방은 목록에 **[확인됨]** 으로 표시됩니다.

### 발송 순서

```
① 열려 있는 채팅방 창으로 보냅니다          ← 사용자가 열어 둔 창
② 남은 방은 카카오톡 목록에서 이름으로 찾습니다
③ 그래도 남으면 목록의 모든 줄을 열어 확인합니다
④ 끝까지 못 보낸 방은 실패로 마무리합니다
```

고른 방이 **모두** 창으로 열려 있으면 ①에서 끝납니다.
카카오톡 목록 창이 최소화돼 있어도, 목록을 못 읽는 상태여도 발송됩니다.

**사용자가 열어 둔 창은 보내고 나서도 닫지 않습니다.** 사용자 것이기 때문입니다.
우리가 목록에서 연 창만 닫습니다.

### 채팅방 창인지 어떻게 가려내나

다섯 가지를 모두 만족해야 채팅방 창으로 봅니다.

1. 카카오톡 프로세스의 창이고
2. 보이는 창이고
3. 메인 창(채팅 목록)이 아니고
4. 글 입력칸(`RICHEDIT50W`)이 있고
5. 대화 목록(`EVA_VH_ListControl_Dblclk`)이 있다

사진 미리보기 창은 4)가 없어서, 프로필 창은 5)가 없어서 걸러집니다.
단체방 제목 뒤의 인원수 `(24)` 는 떼어 냅니다.

### 화면에서 달라진 것

### 무엇을 확인했나

`-SelfTest` 에 시험 두 가지를 더 넣었습니다. 실제 메시지는 한 통도 안 보냅니다.

실제 카카오톡에서는 채팅방 창이 하나 열려 있을 때 그것을 정확히 집어내는 것까지

## v6.0.0 — 발송 방식을 통째로 바꿨습니다

### 무엇을 바꿨나

예전 방식은 이랬습니다.

```
방 이름을 쳐 넣는다 → 검색한다 → 검색 결과를 화면 글자로 읽는다 → 보낸다
```

글자로 읽는 단계가 두 번 들어가 있었습니다. 그래서 `뽀식` 을 `포식` 으로 읽으면
그대로 엉뚱한 방이 열렸고, `투투` 와 `토토` 처럼 비슷한 이름은 서로 섞였습니다.

새 방식은 이렇습니다.

```
카카오톡 목록을 통째로 읽는다
  → 방을 하나 열어 창 제목으로 이름을 확정한다
  → 확정한 이름을 저장한다
  → 저장한 목록만 보고 한 방씩 처리한다
```

창 제목은 화면 글자 인식이 아니라 윈도우가 알려 주는 진짜 글자입니다.
그래서 `뽀식` 은 언제나 `뽀식` 입니다.

**검색으로 방을 찾던 코드는 지웠습니다.** `Open-RoomBySearch`, `Open-RoomFromList`,
`Resolve-RoomName` 은 더 이상 없습니다.

### 1. 채팅방 목록 자동 수집 · 저장 · 새로고침

[2. 받을 채팅방] 화면의 **[채팅방 목록 새로고침]** 이 카카오톡에 보이는 목록을
위에서 끝까지 훑어 통째로 가져옵니다. 이름을 직접 칠 필요가 없습니다.

- **[방을 열어 이름 확인]** 을 켜면 방을 하나씩 열어 창 제목으로 이름을 확정합니다.
  느리지만(방 하나에 2~3초) 이름이 틀리지 않습니다. 기본값은 켜짐입니다.
- 끄면 화면 글자만 읽습니다. 110개 방을 14초에 읽지만 이름이 틀릴 수 있습니다.
- 스크롤을 끝까지 내려가며 읽고, 같은 방은 한 번만 담습니다.
- 읽은 목록은 `config.json` 의 `Roster` 에 저장되어 프로그램을 껐다 켜도 남습니다.
- 새로고침하면 **새로 생긴 방 / 없어진 방** 을 세어 알려 줍니다.
- 오픈채팅 탭만 읽었다면 일반채팅 방을 없어진 것으로 보지 않습니다. 안 본 것뿐입니다.

목록에 방마다 **종류**(일반채팅 1:1 / 일반채팅 단체 / 오픈채팅)와
**이름 확인**(확인됨 / 화면 글자)이 함께 나옵니다.

### 2. 이름은 정확히 같아야 같은 방입니다

`ConvertTo-ExactKey` 는 앞뒤 빈칸과 사이의 겹친 빈칸만 정리하고 글자는 하나도 바꾸지 않습니다.
비슷한 정도로 견주는 일이 발송 판단에서 완전히 빠졌습니다.

```
투투 ≠ 토토        뽀식 ≠ 포식        우리반 공지방 ≠ 우리반 공지방 2기
```

단체방 창 제목 뒤에 붙는 인원수만 떼어 냅니다. `우리반 공지방 (24)` → `우리반 공지방`

**찾는 것은 관대하게, 보내는 것은 엄격하게.**
어느 줄을 열어 볼지는 화면 글자로 대충 고릅니다. 하지만 방을 연 뒤
창 제목이 **정확히** 같지 않으면 보내지 않고 닫습니다.
`투투` 를 찾다가 `토토` 가 열리면 그냥 닫고 계속 찾습니다.

### 3. 한 방씩 완결 처리

```
열기 → 확인 → 첨부 → 첨부 전송 → 문구 → 문구 전송 → 확인 → 닫기 → 다음 방
```

한 방이 완전히 끝나기 전에는 다음 방으로 가지 않습니다.
채팅창을 여러 개 열어 두지 않습니다.
첨부를 먼저 보내고 그다음 문구를 보냅니다.

발송을 시작한 뒤에는 사용자가 다시 누를 것이 없습니다.
예전에 있던 "다른 탭으로 바꿔 주세요" 물음창은 없앴습니다.

### 4. 조용히 빠지는 방이 없습니다

고른 방은 반드시 **발송 완료** 아니면 **실패** 로 끝납니다.

```
전체 발송 대상: 100개
발송 성공: 97개
발송 실패: 3개
총 처리:   100개      ← 언제나 맞아떨어집니다
```

숫자가 맞지 않으면 프로그램이 스스로 `COUNT_MISMATCH` 를 기록에 남깁니다.

찾는 방법은 두 단계입니다.

1. **1회차** — 이름으로 줄을 찾아 엽니다. 빠릅니다.
2. **2회차부터** — 아직 정체를 모르는 줄을 **모두** 열어 창 제목을 확인합니다.
   느리지만 빠뜨리지 않습니다. 화면 글자를 아예 못 읽은 줄도 여기서 잡힙니다.

그러고도 못 찾으면 `ROOM_NOT_FOUND` 로 실패 처리하고 까닭을 남깁니다.

### 5. 방별 상태와 자동 재시도

상태는 여덟 가지입니다.

```
대기 · 채팅방 여는 중 · 채팅방 확인 · 파일 첨부 중 ·
메시지 전송 중 · 발송 완료 · 재시도 · 실패
```

실패한 방은 목록에서 빼지 않고 남겨 두었다가 다음 회차에 다시 해 봅니다.
재시도 횟수는 [설정] → [발송 진행 방식] → **실패 시 재시도** 에서 0~5회로 정합니다.

**이미 보낸 것을 또 보내지 않습니다.** 문구는 갔는데 첨부가 실패해서 다시 할 때,
문구를 두 번 보내면 안 되기 때문입니다. 방마다 어디까지 갔는지 따로 적어 둡니다.

첨부를 하나라도 못 보내면 그 방은 **실패** 입니다. 못 보낸 것을 완료라고 하지 않습니다.

### 6. 발송 기록을 표로 남깁니다

`logs\발송기록-YYYY-MM.csv` 에 쌓입니다. [실행 기록] 화면의
**[발송 기록 표 열기]** 로 바로 열 수 있습니다.

| 시간 | 채팅방 | 메시지 | 첨부 | 결과 | 사유 |
|---|---|---|---|---|---|
| 14:01 | 뽀식 | 기본안내 | image.jpg | 성공 | |
| 14:03 | 토토 | 기본안내 | image.jpg | 실패 | ROOM_NOT_FOUND … |

### 7. 채팅방 선택

- **전체 선택** — 지금 보이는 방을 모두 체크합니다 (검색·필터와 함께 쓰면 편합니다)
- **전체 해제**
- **일반채팅만** / **오픈채팅만** — 종류로 한 번에 고릅니다
- 보기 필터: 전체 / 1:1 / 단체 / 오픈채팅
- 개별 체크와 그룹 기능은 그대로입니다

발송할 때는 종류를 가리지 않습니다. PC 카카오톡의 [채팅] 목록에는
오픈채팅방도 함께 들어 있어서, 한 목록을 훑어 전부 처리합니다.

### 8. 저장 메시지

[1. 보낼 내용] 화면에 **저장 메시지** 칸이 생겼습니다.
자주 쓰는 문구에 이름을 붙여 담아 두고 골라서 불러옵니다.

- 새로 저장 · 덮어쓰기 · 삭제 · 불러오기
- 줄바꿈도 그대로 남습니다
- 불러온 문구의 이름이 발송 기록 표의 [메시지] 칸에 적힙니다

### 9. 무엇을 확인했나

`-SelfTest` 에 **가짜 카카오톡을 만들어 발송 흐름을 통째로 돌려 보는 시험** 을 넣었습니다.
실제 메시지는 한 통도 보내지 않습니다.

가짜 목록에 일부러 어려운 경우를 넣었습니다.

| 방 | 화면에 읽히는 글자 | 노리는 것 |
|---|---|---|
| 뽀식 | `포식` | 이름을 틀리게 읽어도 찾아내는가 |
| 업체B | (아예 못 읽음) | 글자를 못 읽은 줄도 처리하는가 |
| 우리반 공지방 2기 | `우리반 공지방 2기` | `우리반 공지방` 을 찾을 때 여기 보내지 않는가 |
| 토토 | `토토` | 첫 전송이 실패하면 다시 하는가 |
| 없는방 | (목록에 없음) | 조용히 빠지지 않고 실패로 남는가 |

7개를 골라 돌린 결과가 이렇게 나와야 통과입니다.

```
고른 방 7 = 발송 완료 6 + 실패 1
보낸 곳: 뽀식 · 투투 · 토토 · 업체B · 우리반 공지방 · 스마트스토어 블로그 홍보방
보내면 안 되는 곳(우리반 공지방 2기 · 업체A · 포식)에는 한 번도 안 감
상태표의 7개가 모두 '발송 완료' 아니면 '실패' 로 끝남
```

이름 비교도 따로 확인합니다. `투투 ≠ 토토`, `뽀식 ≠ 포식`,
`우리반 공지방 ≠ 우리반 공지방 2기`, `우리반 공지방 (24) = 우리반 공지방`.

실제 카카오톡에서는 **목록 읽기만** 확인했습니다.
110개 방을 20화면에 걸쳐 14초에 읽었고, 방은 하나도 열지 않았으며
메시지도 보내지 않았습니다.

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File .\KakaoRoomScheduler.ps1 -ScanTest -MaskNames
```

### 아직 확인하지 못한 것

- **실제 메시지 전송** — 요청하신 대로 보내지 않았습니다. 직접 확인해 주셔야 합니다.
- **방을 열어 이름 확정하는 정확 스캔** — 방이 열리며 읽음 표시가 되므로 돌리지 않았습니다.
- 오픈채팅 탭 읽기 — 탭 전환이 화면에 반영되지 않는 문제가 남아 있습니다.

## 처음 시작하기

### 준비물

- Windows 10 이상
- PC 카카오톡 (로그인된 상태)
- **한국어 문자 인식** 기능 — 없으면 채팅방 목록을 읽지 못합니다
  설치: `Windows 설정 → 시간 및 언어 → 언어 및 지역 → 한국어 → 언어 옵션 → 광학 문자 인식`

### 실행

1. PC 카카오톡을 켜고 **채팅 목록이 보이게** 창을 띄웁니다. 최소화되어 있거나 트레이로 닫혀 있으면 안 됩니다.
2. `카카오톡봇.cmd`를 더블클릭합니다.
3. **시작 화면**이 뜨면서 순서대로 점검합니다.

```
[정상] 운영체제 확인           Windows 11 / PowerShell 5.1
[정상] 카카오톡 실행 확인       카카오톡 1개를 찾았습니다.
[정상] 카카오톡 창 선택         카카오톡 #20724 / 지금 일반채팅 탭
[정상] 한국어 문자 인식 확인     사용 가능
[정상] 최신 배포 확인           최신 버전입니다.
```

- 다섯 줄이 모두 `[정상]`이어야 `시작하기` 버튼이 나옵니다.
- 카카오톡을 **여러 개 켜 두셨다면** 어느 창을 쓸지 고르는 창이 뜹니다.
- 새 버전이 있으면 **업데이트해야 사용할 수 있습니다.**

처음 실행하면 **가이드 투어**가 뜹니다. 오른쪽 위 `?` 버튼으로 언제든 다시 볼 수 있습니다.

> **한 번에 하나만 실행됩니다.** 두 개를 켜면 설정이 서로 덮어써지고, 같은 카카오톡을 동시에 조작해 엉뚱한 방에 보내질 수 있어 막아 두었습니다. 두 번째 실행은 기존 창을 앞으로 가져오고 종료됩니다.

## 1단계 · 보낼 내용 쓰기

`1. 보낼 내용` 화면입니다.

**발송 문구** — 여기 적은 그대로 나갑니다. **줄바꿈도 그대로 유지**되며, 여러 줄이어도 **한 개의 메시지**로 전송됩니다.

**첨부 사진·파일** — `파일 추가`로 넣고 `위로`·`아래로`로 순서를 바꿉니다. 문구가 먼저 나가고, 그다음 첨부가 목록 순서대로 하나씩 나갑니다.

## 2단계 · 받을 채팅방 고르기

`2. 받을 채팅방` 화면입니다.

### 목록 읽어오기

`카카오톡에서 읽기`를 누르면 지금 카카오톡에서 보고 있는 목록을 훑어 방 이름을 가져옵니다.

읽기 전에 **어느 탭인지 확인**하는 창이 뜹니다. 프로그램이 위쪽 탭 글자를 보고 판별한 결과를 함께 보여 주니 그대로 답하시면 됩니다.

> 읽는 동안에는 마우스와 키보드를 사용하지 마세요.

### 일반채팅과 오픈채팅 나누기 — 순서가 중요합니다

카카오톡 `채팅` 목록에는 **오픈채팅방도 함께 들어 있습니다.** 그래서 탭만으로는 방마다 종류를 알 수 없습니다. 이렇게 하면 정확히 나뉩니다.

1. 카카오톡에서 **`오픈채팅` 탭** → `카카오톡에서 읽기` → 이 방들이 **오픈채팅**으로 표시됩니다
2. 카카오톡에서 **`채팅` 탭** → `카카오톡에서 읽기` → 이미 오픈으로 표시된 방은 **그대로 두고** 나머지만 **일반채팅**이 됩니다

반대 순서로 하셔도 됩니다. **오픈채팅 표시가 항상 우선**이라 나중에 오픈채팅 탭을 읽으면 갱신됩니다.

목록 위의 `전체 / 일반채팅 / 오픈채팅` 버튼으로 걸러 볼 수 있습니다.

### 이름 확인·보정 (꼭 해 주세요)

방 이름은 **화면의 글자를 읽어** 가져오기 때문에 가끔 틀립니다. 보낼 방을 체크한 뒤 `이름 확인·보정`을 누르면, 각 방을 열어 **실제 이름으로 자동 교정**합니다.

- 메시지는 보내지 않지만 채팅방이 열리므로 읽음 표시가 될 수 있습니다.
- 안 잡히는 방은 `직접 추가`로 카카오톡에 보이는 이름 그대로 입력하세요.
- `이름 수정`으로 직접 고칠 수도 있습니다.

> `☆`, `♥`, `&`, 괄호 같은 기호는 화면에서 잘 안 읽힙니다. 프로그램이 기호를 빼고 견주므로 `☆자유로운 홍보방☆`이 `자유로운 홍보방`으로 읽혀도 찾아냅니다.

### 그룹으로 묶기

자주 보내는 방들을 묶어 두면 다음부터 한 번에 고를 수 있습니다.

1. 보낼 방들을 체크합니다
2. `새 그룹 만들기` → 이름 입력 (예: 학부모, 홍보방)
3. 다음부터는 그룹을 고르고 `이 그룹 체크`만 누르면 됩니다

`체크한 방 넣기`로 기존 그룹에 추가할 수 있습니다. `그룹 삭제`는 그룹만 지우고 채팅방 목록은 그대로 둡니다.

### 버튼 정리

| 버튼 | 하는 일 |
| --- | --- |
| `보이는 항목 모두 체크` | 지금 필터에 보이는 것만 체크 |
| `체크 모두 해제` | 전체 체크 해제 |
| `체크한 항목 삭제` | 목록에서만 지웁니다. 카카오톡 채팅방은 그대로입니다 |
| `최대 탐색 화면 수` | 목록을 몇 화면까지 훑을지 (기본 30) |

## 3단계 · 보내기

### 발송 방식

- **실제 발송** — 선택한 모든 방에 문구와 첨부를 보냅니다
- **확인 전용** — 방을 하나씩 열어 이름만 확인하고 **전송하지 않습니다**

### 테스트 모드 (꼭 먼저 해 보세요)

여러 방에 보내기 전에 **한 방에만** 똑같이 보내 결과를 확인합니다.

- `목록에서 고르기` — 저장된 목록에서 검색해 고릅니다
- `나와의 채팅` — 기본값으로 되돌립니다. 아무에게도 가지 않습니다
- `테스트 발송` — 실제와 똑같이 보냅니다. 줄바꿈·사진 순서를 미리 볼 수 있습니다
- `방 확인만` — 채팅창을 열어 이름만 확인하고 전송하지 않습니다

### 지금 실행

`발송 시작`(위쪽) 또는 `지금 실행`을 누르면 **확인 창**이 뜹니다.

- 받는 채팅방 목록 (이름 + 종류)
- 보낼 문구 미리보기
- 첨부 개수
- **예상 소요 시간** — `체크한 300개 · 간격 2초 → 예상 소요 약 18분`

`다음부터 이 확인 창 보지 않기`를 고르면 건너뜁니다.

### 방 사이 간격

방 하나와 다음 방 사이에 쉬는 시간입니다. **0초부터** 설정할 수 있습니다.

방 하나를 처리하는 데 약 **1.6초**가 걸립니다. 여기에 간격이 더해집니다.

| 방 수 | 간격 0초 | 간격 2초 | 간격 5초 |
| --- | --- | --- | --- |
| 50개 | 약 1분 20초 | 약 3분 | 약 5분 30초 |
| 300개 | 약 8분 | 약 18분 | 약 33분 |

> 짧은 시간에 몰아 보내는 것은 **카카오톡 이용 제한의 주된 원인**입니다. 간격을 1~2초 두고 아래 묶음 발송을 함께 쓰시길 권합니다.

### 중지와 일시정지

발송 중에는 위쪽 `발송 시작` 자리에 **`중지`** 가 나타납니다. 누르면 고를 수 있습니다.

- **잠깐 멈추기** — 버튼이 `계속하기`로 바뀝니다. 누르면 이어서 진행합니다
- **완전히 중지** — 남은 방은 보내지 않습니다
- **계속 진행** — 그냥 닫습니다

## 반복 발송과 예약

### 예약

`예약 시각`을 정하고 `예약 시작`을 누릅니다. 기본값은 **다음날 0시**입니다.

`달력에서 고르기`를 누르면 달력과 시·분을 고를 수 있고, 아래에 바로 확인됩니다.

```
2026-08-15 (토) 00:00  ·  약 15시간 뒤
```

자주 쓰는 시각 버튼도 있습니다 — `오늘 밤 9시` / `내일 0시` / `내일 아침 9시` / `10분 뒤`

> 예약 시각까지 **이 프로그램과 PC 카카오톡을 모두 켜 두어야** 합니다. 화면 잠금·절전 상태에서는 동작하지 않습니다.

### 반복 발송

한 번 다 보낸 뒤 일정 시간마다 다시 보냅니다.

```
☑ 반복 발송 — 한 번 다 보낸 뒤 일정 시간마다 다시 보내기
   [ 30 ] 분마다 · 최대 [ 5 ] 회
```

**최대 횟수를 `0`으로 두면** `중지`를 누를 때까지 계속 반복합니다.

### 묶음 발송

`설정` 화면에 있습니다. 한 번에 다 보내지 않고 나눠 보냅니다.

```
묶음 발송  [ 50 ] 개 보낸 뒤  [ 10 ] 분 쉬기   (0개면 쉬지 않고 계속)
```

300개를 50개씩 나눠 10분씩 쉬면 총 약 1시간이 걸리지만, 한꺼번에 몰아 보내는 것보다 안전합니다.

## 발송 제한 (방해금지·주말·공휴일)

`설정` 화면의 **발송 제한 및 묶음 발송** 카드입니다.

- **방해금지 시간대** — 예: `21:00` 부터 `08:00` 까지. 자정을 넘는 구간도 됩니다
- **주말(토·일)에는 보내지 않기**
- **공휴일에는** `평소대로` / `보내지 않음` / `간격 늘리기`(배수 지정)

동작 방식:

- `지금 실행`이 제한에 걸리면 이유와 다음 가능 시각을 보여 주고 한 번 더 확인합니다
- **예약 발송이 제한에 걸리면 취소하지 않고 보낼 수 있는 다음 시각으로 미룹니다**
- 발송 도중 방해금지 시간대로 들어가면 남은 방은 보내지 않고 멈춥니다

공휴일은 양력 고정일과 **음력 명절(설날·추석·부처님오신날)**, 그리고 **대체공휴일**까지 계산합니다. `올해 공휴일 보기`로 실제 목록을 확인하세요.

임시공휴일은 자동으로 알 수 없으므로, 필요하면 `config.json`의 `ExtraHolidays`에 `"2026-10-16"` 형식으로 추가하시면 됩니다.

`지금 확인`을 누르면 지금 상태를 점검합니다.

```
[정상] 카카오톡 연결됨 - 지금 선택된 탭: 일반채팅 탭
[정상] 채팅방 목록을 찾았습니다. (화면 ChatRoomListView)
[정상] 한국어 문자 인식 사용 가능
[안내] 채팅/오픈채팅 탭과 검색 아이콘은 자동으로 찾습니다. 따로 설정할 것이 없습니다.
```

`카카오톡 창 앞으로 가져오기`로 카카오톡을 띄울 수 있습니다.

> **좌표를 맞추는 설정은 없습니다.** 카카오톡 창의 내부 구조를 실행할 때마다 읽어 스스로 찾습니다. 창 크기나 화면 배율을 바꿔도 다시 설정할 필요가 없습니다.

### 업데이트

- `시작할 때 자동 확인` — 실행 직후 조용히 확인
- `새 버전이 있으면 물어보고 바로 받기` — 확인 한 번으로 내려받기·설치·재시작까지
- `로그 파일 모두 지우기` — 실행 기록 파일을 모두 삭제 (되돌릴 수 없습니다)

새 버전이 있으면 **업데이트해야 사용할 수 있습니다.** 기존 파일은 `backup\날짜-시각\` 폴더에 보관되고 설정은 유지됩니다.

`가이드 다시 보기` / `프로그램 폴더 열기` / `로그 폴더 열기` / `설정 초기화`

## 잘못 보내지 않도록 하는 안전장치

이 프로그램은 **틀리면 보내지 않는 쪽**으로 만들어졌습니다.

1. **창 제목 확인** — 방을 연 뒤 채팅창 제목이 정확히 일치하지 않으면 닫고 건너뜁니다
2. **입력 내용 확인** — 입력칸에 넣은 글을 다시 읽어 문구와 다르면 **보내지 않습니다**
3. **전송 성공 확인** — 카카오톡은 전송에 성공하면 입력칸을 비웁니다. 이걸로 성공을 판단하며, 실패하면 입력칸을 비우고 실패로 기록합니다
4. **중복 전송 방지** — 이미 보내진 뒤에는 입력칸이 비어 있어 다음 시도가 아무 일도 하지 않습니다
5. **한 번에 최대 500개**

## 자주 묻는 것

**발송 중에 컴퓨터를 써도 되나요?**

권하지 않습니다. 방을 열고 닫고 목록을 넘기는 일은 백그라운드로 처리되지만, **전송하는 순간에는 채팅창이 잠깐 앞으로 나와야 합니다**(방당 약 1초). 카카오톡이 프로그램으로 넣은 글자를 사용자 입력으로 인정하지 않아 실제 키보드 입력이 필요하기 때문입니다. 그때 타자를 치시면 그 글자가 채팅창으로 들어갈 수 있습니다.

자리를 비우는 시간대에 **예약**해 두시는 쪽을 권합니다.

**마우스는 움직이나요?**

아니요. 마우스 커서는 건드리지 않습니다.

**카카오톡을 여러 개 켜 두었는데요?**

시작 화면에서 어느 창을 쓸지 고릅니다. 고른 창에만 보냅니다.

**여러 줄 문구를 보내면 줄마다 따로 가나요?**

아니요. 줄바꿈은 Shift+Enter로 처리해 **한 개의 메시지**로 보냅니다.

**동명 채팅방이 있으면요?**

구분할 수 없습니다. 카카오톡에서 방 이름을 서로 다르게 바꾼 뒤 사용하세요.

## 다른 사람에게 넘기거나, 처음부터 다시 하고 싶을 때

이 프로그램은 **설정과 실행 기록을 프로그램 폴더 안에 보관합니다.**

```
config.json   받을 채팅방 목록, 문구, 예약 설정
logs/         지난 실행 기록 (보낸 방 이름이 들어 있습니다)
backup/       업데이트 전 프로그램 파일 (개인 정보 없음)
```

새로 내려받아도 **같은 폴더에 풀면 config.json 과 logs 가 그대로 남습니다.** 설정을 지키려고 일부러 그렇게 만들었습니다.

그래서 **폴더째로 다른 사람에게 주면 내 채팅방 목록과 실행 기록도 같이 갑니다.**

`설정` 화면 맨 아래 **`처음 상태로 되돌리기`** 를 누르면 config.json 과 logs 를 모두 지우고 처음 받은 상태가 됩니다. 폴더를 넘기기 전에 이 버튼을 눌러 주세요.

깨끗한 상태로 새로 쓰고 싶을 때도 같은 버튼입니다.

## 사진·파일 첨부

오랫동안 첨부가 안 갔던 이유를 찾았습니다.

카카오톡은 사진을 붙여넣으면 채팅창에 바로 붙이지 않고 **`클립보드 이미지 전송` 이라는 미리보기 창을 따로 띄웁니다.** 그 창에서 `전송`을 눌러야 실제로 갑니다. 예전 코드는 이 창의 존재를 몰라서 채팅창만 보고 "안 붙었다"고 판단했고, 그래서 `전송`을 누르지 않았습니다.

지금은 이렇게 동작합니다.

```
사진   붙여넣기 → 미리보기 창 확인 → 그 창의 [전송] 누름 → 창이 닫히면 성공
문서   [파일] 아이콘 → 파일 선택창에 경로 입력 → [열기] → 전송
```

한쪽이 막히면 다른 쪽으로 자동으로 넘어갑니다.

**보냈는지 확인하는 방법도 바꿨습니다.** 예전에는 입력칸이 비었는지를 봤는데, 첨부는 입력칸이 처음부터 비어 있어 항상 성공으로 보였습니다. 지금은 **전송 버튼이 노랗게 켜졌다가 꺼지는 것**과 **미리보기 창이 닫히는 것**으로 확인합니다.

**확인되지 않으면 보내지 않고 붙인 것을 치웁니다.** 잘못 보내는 것보다 안 보내는 것이 낫습니다.

### 먼저 시험해 보세요

`1. 보낼 내용` 화면의 **`첨부 시험`** 버튼을 누르면 첨부가 붙는지만 확인하고 **보내지 않습니다.** 실제 발송 전에 이 환경에서 첨부가 되는지 미리 알 수 있습니다.

## 오픈채팅에서 전송이 안 되던 문제

방은 열리는데 글이 안 나가던 이유를 실제로 재서 찾았습니다.

```
창 제목과 입력칸이 준비되는 시간      약 0.4초
대화 내용을 다 불러오는 시간          0.9초 ~ 12초  (방마다 다름)
```

**대화를 불러오는 중에는 Enter 를 눌러도 아무 일이 없습니다.** 예전 코드는 0.4초에 보내 버려서, 12초짜리 방은 계속 실패했습니다.

지금은 **화면이 멈출 때까지 기다린 뒤** 보냅니다. 그리고 **보낸 뒤 확인해서 안 갔으면 다시 보냅니다.**

다시 보내기 전에 **입력칸을 반드시 확인합니다.** 비어 있으면 이미 간 것이므로 다시 보내지 않습니다. 같은 글이 두 번 가는 일을 막습니다.

`설정 → 대화 로딩 대기` 에서 기다리는 시간을 정할 수 있습니다. 기본 4초이고, 오픈채팅이 많으면 10~15초로 올려 주세요.

### 이름이 잘린 방도 찾습니다

카카오톡 목록은 이름이 길면 뒤를 `…` 로 줄여 보여 줍니다. 예전에는 이 잘린 이름이 창 제목과 달라서 그 방들이 전부 건너뛰어졌습니다.

지금은 앞부분이 같으면 같은 방으로 봅니다. 다만 **앞부분이 같은 방이 둘 이상이면 보내지 않습니다.** 엉뚱한 방에 보내는 것보다 안 보내는 것이 낫습니다.

### 방 이름 정리

읽어 온 이름에서 아래를 걷어냅니다.

```
안 읽은 개수 뱃지    0 홍보방      →  홍보방
잘림 표시            긴 방이름…    →  긴 방이름
인식 찌꺼기          폰고 ′,       →  폰고
이모티콘·그림문자
```

진짜 이름이 숫자로 시작하는 방(`5K 디자인`, `95 비와이`)은 **그대로 둡니다.**

**이미 읽어 둔 목록에는 옛 이름이 남아 있습니다.** `2. 받을 채팅방 → 카카오톡에서 읽기` 를 한 번 다시 눌러 주세요.

### 목록을 종류로 나누지 않습니다

오픈채팅과 일반채팅을 따로 묶지 않고 **이름 순서 한 줄로** 보여 줍니다. 종류로 골라 보고 싶을 때만 위쪽 `개인` `그룹` `오픈채팅` 버튼을 쓰면 됩니다.

## 어떤 컴퓨터는 되고 어떤 컴퓨터는 안 되던 이유

예전 방식은 **두 가지에 기대고 있었습니다.** 둘 다 그 컴퓨터가 그때 어떤 상태냐에 따라 달라집니다.

```
1. 클립보드    다른 프로그램이 잡고 있으면 못 씁니다
2. 창 활성화   윈도우가 막으면 창을 앞으로 못 가져옵니다
```

실제로 이 PC 에서 재봤더니 **클립보드는 12번 시도해도 전부 실패**했습니다. 다른 프로그램이 계속 붙잡고 있었습니다. 그리고 창 활성화는 원격 데스크톱으로 접속했거나, 다른 창을 쓰고 있거나, 화면이 잠기면 막힙니다.

예전 코드는 창을 앞으로 못 가져오면 **아무것도 안 하고 그냥 포기**했습니다. 그래서 되는 컴퓨터와 안 되는 컴퓨터가 갈렸습니다.

### 지금은 둘 다 필요 없습니다

확인해 보니 카카오톡은 **창 메시지로 넣은 글도 사람이 친 것으로 인정합니다.**

```
창 메시지로 글 넣기      [안녕하세요 테스트]    전송버튼 켜짐
창 메시지로 백스페이스   먹음
창 메시지로 방향키       먹음
창 메시지로 여러 줄 넣기 3줄 그대로, 전송버튼 켜짐
```

**전부 창을 앞으로 가져오지 않은 상태에서 된 것입니다.**

그래서 이제 이 순서로 합니다.

```
1순위  창 메시지로 끼워 넣기   클립보드 X, 창 활성화 X   ← 거의 항상 됩니다
2순위  한 글자씩 넣기          클립보드 X, 창 활성화 X
3순위  클립보드 붙여넣기
4순위  창을 앞으로 가져와 키보드
```

앞의 것이 실패해야 다음으로 넘어갑니다. **어느 하나가 막혀도 발송이 멈추지 않습니다.**

덤으로, 이제 **마우스와 키보드를 쓰면서도 발송이 됩니다.** 창이 앞으로 튀어나오지 않습니다.

## 300개 방을 10분 안에 보내려면

한 방에 드는 시간은 이렇습니다.

```
방 열기            약 0.3초
제목·입력칸 확인   약 0.4초
대화 로딩 대기     0.4초 ~ 설정한 시간
글 넣고 보내기     약 0.5초
──────────────────────────────
합계               약 1.6초 ~
```

여기에 **방과 방 사이 간격**이 더해집니다. `설정 → 발송 간격` 이 **기본 8초**입니다.

```
간격 8초  →  300 × (1.6 + 8) = 약 48분
간격 2초  →  300 × (1.6 + 2) = 약 18분
간격 1초  →  300 × (1.6 + 1) = 약 13분
간격 0초  →  300 × 1.6       = 약 8분
```

**300개를 10분 안에 보내시려면 간격을 0~1초로 두셔야 합니다.** 다만 간격을 너무 줄이면 카카오톡이 이용을 제한할 수 있습니다. 처음에는 2초 정도로 해 보시고 늘리거나 줄이시는 것을 권합니다.

`대화 로딩 대기` 도 시간에 그대로 더해집니다. 오픈채팅이 많으면 늘려야 하지만, 늘린 만큼 전체가 느려집니다.

예전에는 `방 사이 간격`과 `반복`이 **보내기 화면**에 있고, 나머지가 **설정 화면**에 있어서 어디서 바꿔야 하는지 헷갈렸습니다.

이제 **모든 설정은 `설정` 화면 한 곳**에 있습니다. `설정 → 발송 진행 방식` 에 이렇게 모았습니다.

```
방 사이 간격      0~300초
방 열림 대기      3~60초
대화 로딩 대기    0~30초
처음 보내기 전에 방 미리 열기
반복 발송         몇 분마다 · 최대 몇 회
```

`보내기` 화면에는 **지금 어떻게 설정돼 있는지 요약만** 보입니다. 바꾸려면 그 옆 `설정에서 바꾸기` 를 누르면 됩니다.

## 처음 쓰실 때 — 방 미리 열기

카카오톡을 막 켰거나 이 프로그램을 처음 쓰시면, 채팅방마다 대화를 **처음부터 새로 불러옵니다.** 방에 따라 12초까지 걸리고, **다 불러오기 전에는 전송이 되지 않습니다.**

그래서 **처음 보낼 때는 대상 방을 먼저 한 번씩 열어 둡니다.** 기본으로 켜져 있고, 처음 한 번만 합니다.

```
방 미리 열기: 300개를 한 번씩 열어 대화가 다 불러와지는지 봅니다.
보내지 않습니다. 처음 한 번만 하면 되고, 이후 발송이 훨씬 안정적입니다.
...
방 미리 열기 끝: 확인 297개 / 열지 못함 2개 / 목록에서 못 찾음 1개
```

한 번 열어 둔 방은 카카오톡이 기억하고 있어서 다음부터 금방 열립니다. 언제든 `설정 → 지금 미리 열기` 로 다시 하실 수 있습니다.

**메시지는 보내지 않습니다.** 방을 열어 확인만 합니다.

## 프로그램으로 실행하기 (다른 컴퓨터에서 쓰기 좋습니다)

배포 파일 안에 **`카카오 발송기.exe`** 가 들어 있습니다. **두 번 누르면 바로 실행됩니다.**

파워셸이나 실행 정책을 몰라도 되고, `.cmd` 를 거치지 않아도 됩니다. 다른 컴퓨터에 폴더째 복사해서 바로 쓰시면 됩니다.

```
카카오 발송기.exe        ← 이것만 두 번 누르면 됩니다
KakaoRoomScheduler.ps1   같은 프로그램의 스크립트 판 (예전 방식)
카카오톡봇.cmd            스크립트 판 실행기
```

**설정과 기록은 프로그램이 있는 폴더 안에 만들어집니다.** 폴더째 옮기면 설정도 같이 갑니다.

업데이트도 그대로 됩니다. 실행 중인 프로그램 파일은 자기 자신을 덮어쓸 수 없어서, 새 파일을 옆에 받아 두었다가 **다시 시작할 때 바꿔치기**합니다.

스크립트 판(`.ps1`)도 그대로 들어 있으니 원래 쓰시던 방식도 계속 됩니다.

## 채팅방 목록이 저절로 정리됩니다

예전에 저장된 이름에는 안 읽은 개수 뱃지나 잘림 표시가 그대로 남아 있어서, 같은 방이 두 번 보이곤 했습니다.

```
*자유로운 홍보방*
0 *자유로운 홍보방*    ← 같은 방인데 뱃지가 붙어 따로 저장됨
0 [ZZAN] 기TTME/RHY…
```

이제 **프로그램을 켤 때 한 번 정리하고 같은 방은 합칩니다.** 종류와 그룹 정보도 함께 옮겨집니다.

실제로 정리한 결과입니다.

```
채팅방 목록을 정리했습니다: 이름 다듬음 32개 · 같은 방 합침 16개
192개  →  179개
```

## 실패하면 까닭을 남깁니다

예전에는 발송이 실패해도 **채팅창이 켜졌다 바로 꺼지기만** 하고 왜 그런지 알 수 없었습니다.

이제 무엇 때문인지 `실행 기록` 에 남습니다.

```
실패: '우리반 공지방' — 글을 넣는 중 문제가 생겼습니다: ...
실패: '우리반 공지방' — 입력칸에 문구를 넣지 못했습니다.
실패: '우리반 공지방' — Enter 를 눌러도 전송되지 않았습니다. (대화를 아직 불러오는 중일 수 있습니다)
```

## 보내지도 않고 완료라고 하던 문제

**가장 나쁜 종류의 버그였습니다.** 글이 실제로 가지 않았는데 `작업 완료` 라고 알렸습니다.

원인은 두 가지가 겹친 것입니다.

**1. 넣는 방법을 잘못 골랐습니다.** 창 메시지로 입력칸에 글을 넣으면 **전송 버튼이 노랗게 켜집니다.** 그래서 카카오톡이 받아들인 줄 알았습니다. 그런데 Enter 를 누르면 **카카오톡이 그 글을 그냥 지워 버리고 보내지 않습니다.**

**2. 성공 판정이 틀렸습니다.** "입력칸이 비었으면 보낸 것"으로 봤습니다. 카카오톡이 글을 지워도 입력칸은 비므로, **지워진 것을 보낸 것으로 착각**했습니다.

### 고친 방법

**넣는 순서를 되돌렸습니다.** 사람이 직접 친 것과 같은 방법을 먼저 씁니다.

```
1순위  실제 붙여넣기   창을 앞으로 가져와 Ctrl+V
2순위  실제 키보드     창을 앞으로 가져와 직접 입력
3순위  창 붙여넣기     창 메시지로 붙여넣기
4순위  창 메시지       마지막 수단
```

**진짜 갔는지 대화창을 보고 확인합니다.** 입력칸이 비는 것만으로는 판단하지 않습니다. 대화창 아래쪽에 **새 말풍선이 생겼는지** 봅니다.

```
가만히 있을 때 지문 같은가   True
안 보낸 상태에서 "갔는가"    False   ← 거짓 성공 없음
입력칸에 글자만 넣었을 때    False   ← 속지 않음
```

한 방법으로 안 가면 다음 방법으로 다시 넣어 봅니다. **끝까지 확인되지 않으면 실패로 알리고, 왜 그런지 기록에 남깁니다.**

```
실패: '방이름' — '창 메시지' 로 넣은 글을 카카오톡이 지웠습니다. 보내지지 않았습니다.
```

## 화면을 새로 만들었습니다

밝고 단순하게 다시 그렸습니다.

```
검은 사이드바      →  흰 바탕에 얇은 선 하나
카드 테두리        →  없앰. 흰 면과 여백만으로 구역을 나눔
단추 테두리        →  없앰. 옅은 회색 면으로 표시
노란 단추 13개     →  4개 (실제로 보내는 것만)
```

**노란색은 실제로 보내는 단추에만 씁니다.** `발송 시작`, `지금 실행`, `테스트 발송`, `보내기`. 나머지 중요한 단추는 짙은 회색으로, 보조 단추는 옅은 회색으로 구분됩니다. 어디를 눌러야 실제로 보내지는지 한눈에 보입니다.

첨부 목록에는 긴 경로 대신 **파일 이름만** 보입니다.

화면 요소가 서로 겹치지 않는지 **검사로 확인**합니다. 눈으로 놓치던 것을 잡아 줍니다.

## 방만 열고 아무것도 안 보내던 이유

**`확인 전용` 모드로 돌고 있었습니다.**

이 모드는 방을 하나씩 열어 이름만 확인하고 **아무것도 보내지 않습니다.** 연습용입니다. 그런데 두 가지가 겹쳐 알아채기 어려웠습니다.

```
새로 설치하면 기본값이 확인 전용이었습니다
끝나면 '작업 완료' 라고 나와 보낸 줄 알기 쉬웠습니다
```

증상이 정확히 이렇습니다. **채팅방은 열리는데 입력칸에 아무것도 안 들어가고, 그래도 완료라고 나옵니다.**

### 고쳤습니다

**기본값을 `실제 발송` 으로 바꿨습니다.** 새로 설치하면 바로 보낼 수 있습니다.

**확인 전용일 때는 완료라고 하지 않습니다.**

```
확인만 함: '방이름' — 방은 열렸습니다. 아무것도 보내지 않았습니다.
확인 전용으로 끝났습니다: 방 12개를 열어 보았고, 실제로 보낸 메시지는 없습니다.
실제로 보내시려면 [3. 보내기] 화면에서 [실제 발송] 을 고르세요.
```

**화면 맨 위에 항상 보입니다.** 확인 전용이면 붉은 글씨로 `확인 전용 — 보내지 않습니다` 가 뜨고, 시작 단추 이름도 `확인 시작` 으로 바뀝니다.

## 복사해 둔 내용이 대신 나가던 문제

글을 넣을 때 **클립보드에 우리 문구를 넣고 Ctrl+V** 를 누릅니다. 그런데 클립보드에 넣는 것이 **성공한 것처럼 보여도 실제로는 반영되지 않는 경우**가 있습니다. 다른 프로그램이 클립보드를 잡고 있을 때 그렇습니다.

그러면 **사용자가 복사해 두었던 엉뚱한 내용이 그대로 붙어 나갑니다.**

이제 **누르기 직전에 클립보드를 다시 읽어 확인**합니다.

```
넣고 확인          True    → 붙여넣기 진행
다른 내용일 때     False   → 붙여넣기 건너뛰고 직접 입력으로
```

우리 문구가 아니면 **붙여넣지 않고 다른 방법으로 넘어갑니다.**

### 복사해 두신 것도 지켜 드립니다

발송을 시작할 때 클립보드에 있던 것을 챙겨 두었다가 **끝나면 되돌려 놓습니다.** 발송했다고 복사해 둔 것이 날아가지 않습니다.

### 기록에 문구 길이가 남습니다

```
작업 시작: 방 3개 / 모드=실제 발송 / 간격 0초
보낼 문구 491자 / 첨부 1개
```

문구가 `0자` 로 나오면 보낼 내용이 비어 있는 것입니다.

## 어떤 컴퓨터에서 아예 전송이 안 되던 이유

**입력칸이 키보드 입력을 받는 상태가 아니었습니다.**

우리가 방금 연 방은 대개 입력칸이 활성화되어 있습니다. 그런데 **이미 열어 두셨던 방**은 포커스가 대화 목록 쪽에 가 있거나, **아예 아무 칸도 포커스를 받지 않은 상태**일 수 있습니다.

실제로 재 봤습니다.

```
지금 키보드 입력을 받는 칸 : 0        ← 아무 데도 없습니다. Enter 가 갈 곳이 없습니다
포커스를 맞춘 뒤           : 입력칸  (341ms)
```

이제 **글을 넣기 전과 Enter 를 누르기 전에 입력칸에 확실히 포커스를 맞춥니다.** 세 번까지 확인하고, 안 되면 입력칸을 눌러 줍니다.

## 엉뚱한 방이 열리던 문제

기록을 보니 이런 일이 벌어지고 있었습니다.

```
'마케팅 자유 홍보.-'  →  실제로 열린 창: '자유홍보 광고/마케팅 공유방'
'자유홍보 광고/마'    →  실제로 열린 창: '무한,광고,홍보,유통,제조,소통,'
'스마트스토어 불로'   →  실제로 열린 창: '스마트스토어 블로그 인스타그램 홍보방...'
```

**저장된 이름으로 목록을 뒤지는 방식 자체가 한계였습니다.** 목록에 보이는 이름은 길면 잘리고, 화면 글자 인식도 가끔 틀립니다(`블` → `불`). 그러니 비슷한 다른 줄이 걸려 엉뚱한 방이 열렸습니다.

### 창 제목을 기준으로 삼습니다

**창을 열고 나면 제목은 정확한 글자로 읽을 수 있습니다.** 이제 그것을 기준으로 합니다.

```
1. 목록에서 비슷한 줄을 눌러 방을 엽니다
2. 열린 창의 제목을 읽습니다          ← 이것이 정답입니다
3. 보낼 목록 중 어느 방인지 다시 정합니다
4. 맞으면 그 방으로 보냅니다
5. 저장된 이름을 실제 제목으로 바꿔 둡니다   ← 다음부터는 헤매지 않습니다
```

**보낼 목록에 없는 방이 열리면 닫고 지나갑니다.** 그 줄은 다시 고르지 않습니다.

**두 방이 비슷하게 걸리면 보내지 않습니다.** 어느 쪽인지 모르는 채로 보내는 것보다 안 보내는 편이 낫습니다.

### 확인한 것

```
통과  '자유홍보 광고/마케팅 공유방'          → '자유홍보 광고/마'    (잘린 이름)
통과  '스마트스토어 블로그 인스타그램...'    → '스마트스토어 불로'   (글자 인식 오류)
통과  '※자유 홍보 방 ※ 와서 홍보 하세요!'   → '※자유 홍보 방 ※'    (기호 포함)
통과  '무한,광고,홍보,유통,제조,소통,'       → 없음                 (목록에 없는 방)
통과  비슷한 방이 둘일 때                     → 없음                 (헷갈리면 안 보냄)
```

이름 다듬기도 넓혔습니다.

```
0※자유 홍보 방 ※   →  ※자유 홍보 방 ※      기호 앞에 붙은 뱃지
마케팅 자유 홍보.-  →  마케팅 자유 홍보      줄 끝 찌꺼기
```

## 보낸 뒤에 또 쓰던 과정을 없앴습니다

붙여넣기로 보낸 뒤, **대화창에 올라왔는지 확인**하고 확인이 안 되면 다음 방법(직접 입력)으로 **다시 써 넣고 있었습니다.** 실제로는 이미 갔는데도 그랬습니다.

화면에 글자가 하나씩 다시 써지는 것이 보이고, **같은 글이 두 번 갈 위험**도 있었습니다.

이제 이렇게 나눕니다.

```
실제 붙여넣기 / 실제 키보드   입력칸이 비워지면 그것이 곧 전송입니다. 더 확인하지 않습니다
창 붙여넣기 / 창 메시지        카카오톡이 글을 지우기도 하므로 대화창을 확인합니다
```

사람이 직접 치는 것과 같은 방법으로 넣은 글은 카카오톡이 지우지 않습니다. 그래서 다시 쓸 이유가 없습니다.

**한 번 통한 방법은 기억해 두었다가 다음 방부터 먼저 씁니다.** 안 되는 방법을 방마다 다시 시도하지 않으므로 300개 발송이 눈에 띄게 빨라집니다. 확인이 필요 없는 방법일 때는 화면도 뜨지 않습니다.

## 설치해서 쓰기

배포에 **`KakaoSender-Setup-v버전.exe`** 가 함께 올라갑니다. 두 번 누르면 설치됩니다.

```
설치 위치     내 계정 폴더 (관리자 권한이 필요 없습니다)
시작 메뉴     카카오 발송기 · 사용설명서 · 제거
바탕 화면     아이콘 (원하시면)
```

**관리자 권한을 묻지 않습니다.** 이 프로그램은 설정과 실행 기록을 자기 폴더 안에 만드는데, `Program Files` 에 넣으면 권한 때문에 쓰지 못합니다. 그래서 내 계정 폴더에 설치합니다.

제거는 **시작 메뉴 → 카카오 발송기 → 제거** 또는 윈도우 `설정 → 앱` 에서 하시면 됩니다. 제거할 때 **설정과 기록도 함께 지웁니다.**

설치가 싫으시면 예전처럼 **`카카오 발송기.exe` 만 받아서 원하는 폴더에 두고 쓰셔도 됩니다.**

## 전송 버튼이 먹통이 되던 증상

붙여넣기로 글을 넣으면 **글자는 들어가는데 전송 버튼이 안 켜지는** 경우가 있습니다. 카카오톡이 붙여넣은 글을 사람이 친 것으로 인정하지 않은 것입니다.

예전에는 그 상태에서 그냥 Enter 를 눌러 봤습니다. 당연히 먹통이고, 그제서야 다른 방법으로 넘어가 **글을 다시 써 넣었습니다.**

이제 **Enter 를 누르기 전에 전송 버튼부터 봅니다.**

```
글자가 제대로 들어갔는가       →  아니면 다른 방법으로
전송 버튼이 켜졌는가            →  아니면 한 번 깨워 봅니다
깨워도 안 켜지는가              →  Enter 를 누르지 않고 직접 입력으로
```

깨우기는 **공백을 하나 넣었다 지우는 것**입니다. 그러면 진짜 입력이 있었던 것이 되어 버튼이 켜지고, 빠른 붙여넣기를 그대로 쓸 수 있습니다.

기록에 남습니다.

```
'실제 붙여넣기' 로 넣은 뒤 전송 버튼이 꺼져 있어 한 번 깨웠습니다.
'실제 붙여넣기' 로 넣었지만 전송 버튼이 켜지지 않아 다른 방법으로 넘어갑니다.
```

**타이핑은 붙여넣기가 안 될 때만 합니다.** 이미 보낸 뒤에 다시 쓰는 일은 없습니다.

## 필수 요소 확인

이 프로그램이 돌아가려면 몇 가지가 있어야 합니다. **`설정 → 필수 요소 확인`** 을 누르면 확인하고, 없는 것은 설치까지 해 줍니다. 무엇을 확인하는 중인지 한 줄씩 보이고, 다 준비되어 있으면 **바로 프로그램을 띄웁니다.** 설치 프로그램을 쓰시면 설치 직후에도 한 번 물어봅니다.

```
윈도우 10 이상
.NET Framework 4.7.2 이상    프로그램이 이것으로 돌아갑니다
한국어 문자 인식 (OCR)        채팅방 이름을 읽는 데 씁니다
PC 카카오톡                   로그인까지 되어 있어야 합니다
```

**한국어 문자 인식이 가장 중요합니다.** 카카오톡 채팅방 목록은 글자를 내놓지 않아서 화면을 떠서 읽는데, 이 기능이 없으면 **목록을 한 개도 읽지 못합니다.**

없으면 자동으로 설치합니다. 설치에는 관리자 권한이 필요해서 창이 하나 더 뜹니다. `[예]` 를 눌러 주세요.

```
==========================================
  카카오 발송기 — 필수 요소 확인
==========================================

  [정상] 윈도우: Microsoft Windows 11 Pro (빌드 26200)
  [정상] .NET Framework 4.7.2 이상 (Release 533509)
  [정상] 한국어 문자 인식 (채팅방 이름 읽기)
  [정상] PC 카카오톡 (지금 켜져 있습니다)

필요한 것이 모두 준비되어 있습니다. 그대로 쓰시면 됩니다.
```

## 채팅방 이름을 잘못 읽던 문제

카카오톡 채팅 목록은 **글자를 내놓지 않습니다.** 확인해 봤습니다.

```
UI Automation   자손 요소 1개, 글자 없음
MSAA            자식 7개, 이름·값·설명 모두 비어 있음
창 메시지       컨트롤 이름만 나옴 (ChatRoomListCtrl_0x...)
```

카카오톡이 목록을 직접 그리기 때문입니다. **화면을 떠서 글자로 읽는 것 외에 방법이 없습니다.**

### 확대 배율이 문제였습니다

목록 글자가 작아서 그대로 읽으면 자주 틀립니다. 배율을 바꿔 가며 재 봤습니다.

```
확대 2배 (예전)   [트4규형]   [서인금융진흥원]   5개 읽음
확대 3배          [트4규형]   [서인금융진흥원]   6개 읽음
확대 4배          [택규형]    [서민금융진흥원]   6개 읽음   ← 정확
```

**4배가 정확하고 속도도 같았습니다** (340ms vs 360ms). 이제 창 폭에 맞춰 **2~4배 사이에서 자동으로 정합니다.**

바꾼 뒤 전체를 읽어 보니 **62개 / 6.5초**, 그리고 짧은 이름도 잘 읽힙니다.

```
4XR · H&M · JOY · lng · 마이클 · 쏘가 · 아정당 · 우정방 · 이도 · 토스 · 현우씨
```

### 한 글자 오인식으로 같은 방이 둘로 남던 것

```
[5K X 아우여 (따몽이)]
[5K X 아우여 (따봉이)]    ← 같은 방
```

길이가 같고 **한 글자만 다르면** 같은 방으로 보고 합칩니다. 다만 **여덟 자 이상일 때만** 합칩니다. 짧은 이름은 진짜 다른 방일 수 있기 때문입니다.

### 그래도 남는 오인식은

발송할 때 **창 제목으로 바로잡습니다.** 목록 글자는 부정확해도 창 제목은 정확합니다. 한 번 바로잡히면 그 다음부터는 정확한 이름으로 찾습니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
| --- | --- |
| 카카오톡을 찾지 못함 | PC 카카오톡 실행 여부. 트레이(시계 옆)로 닫혀 있으면 아이콘을 눌러 창을 열어 주세요 |
| 목록을 읽었는데 0개 | 카카오톡에 채팅 목록이 보이는 상태인지, 한국어 문자 인식이 설치됐는지 확인 |
| 방을 못 찾고 건너뜀 | 체크한 뒤 `이름 확인·보정` 실행. 그래도 안 되면 `직접 추가` |
| 오픈채팅방이 안 읽힘 | 카카오톡에서 `오픈채팅` 탭으로 바꾼 뒤 다시 읽기 |
| 전송이 안 됨 | `실행 기록`에서 `전송 방식:` 또는 `실패:` 줄을 확인 |
| 이미 실행 중이라고 나옴 | 정상입니다. 기존 창을 쓰세요. 창이 안 보이면 작업 관리자에서 `powershell` 종료 |
| 한글이 깨져 보임 | 파일이 UTF-8 BOM으로 저장됐는지 확인 |

기록은 `logs\날짜.log` 파일에도 남습니다. 문제를 알려 주실 때 이 파일이 도움이 됩니다.

## 관리자용 — 배포하기

어디서든, 휴대폰 브라우저에서도 수정하고 배포할 수 있습니다.

**GitHub 웹에서**: 저장소에서 파일 수정 → `Actions` 탭 → `release` → `Run workflow` → 버전 입력

**이 PC에서**: `.\Publish-Release.ps1 -Version 4.9.1 -Notes "변경 내용"`

**태그로**: `git tag v4.9.1 && git push origin v4.9.1`

> 스크립트는 **UTF-8 BOM**으로 저장해야 합니다. PowerShell 5.1은 BOM이 없으면 한글을 깨뜨립니다. 배포 워크플로가 자동으로 BOM을 넣어 주지만, 직접 편집하실 때는 주의하세요.

### 개발자 명령

```
카카오톡봇.cmd 대신 아래처럼 실행하면 화면 없이 점검만 합니다.

powershell -NoProfile -ExecutionPolicy Bypass -STA -File .\KakaoRoomScheduler.ps1 -SelfTest
powershell -NoProfile -ExecutionPolicy Bypass -STA -File .\KakaoRoomScheduler.ps1 -ScanTest -MaskNames
```

`-SelfTest`는 설정 구조, 이름 필터, 행 분리, 공휴일 계산, 문구 변환 등을 점검합니다.
`-ScanTest`는 창을 띄우지 않고 채팅방 목록 읽기만 실행합니다.
